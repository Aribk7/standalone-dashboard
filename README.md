# Loop Analytics

A standalone subscription-analytics dashboard for 24F clients. A client pastes
their 24F Client API key once, gets an 8-digit PIN, and from then on opens the
dashboard on any device with that PIN. Devices that have signed in stay signed in.

The dashboard reads only the read-only [24F Client API v1](https://24f.site/api/finance/v1)
using the client's own key. It contains no 24F internals.

## How it works

- **Connect:** the key is checked against 24F (`/connections`), encrypted with
  AES-256-GCM and stored. The key is never sent back to the browser.
- **PIN:** generated by the server (8 digits, unique across all dashboards) and
  shown once. Only a keyed HMAC of it is stored. Wrong guesses are limited per
  network address and site-wide.
- **Session:** an httpOnly cookie with a random token (only its hash is stored),
  re-issued on every visit so returning devices stay signed in.
- **Data:** the server calls 24F with the stored key and caches each report for
  15 minutes per account, keeping well inside 24F's 60 requests/minute limit.

## Setup

1. **Database:** connect a Supabase project to the Vercel project (Vercel →
   Integrations → Supabase) and link this repo in Supabase's GitHub integration
   (working directory `.`, production branch `main`). Migrations in
   `supabase/migrations/` are applied on every push to `main`.
2. **Secret (optional):** `APP_SECRET` in Vercel's environment variables. If it
   is not set, the server derives one from the Supabase server key.
3. **Deploy:** push to `main`; Vercel builds and deploys.

## Local development

```bash
pnpm install
pnpm dev
```

Without Supabase variables the app uses an in-memory store, and "explore with
sample data" signs in to a fictional demo store.

## Stack

Next.js 16 (App Router), React 19, Tailwind CSS 4, Motion, d3-scale/d3-shape,
TanStack Query, Supabase.
